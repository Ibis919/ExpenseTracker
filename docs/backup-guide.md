# 备份、恢复与换机指南

本指南说明三种数据副本各自能做什么，以及误删、换机、重装时该选哪一种。若要把数据带到另一台设备，请优先用「完整备份」，不要把本机自动备份或 CSV 当成完整账本迁移文件。

## 先选备份方式

| 方式 | 如何生成/找到 | 包含 | 不包含 | 适合场景 |
|---|---|---|---|---|
| 完整备份 JSON | 设置 → 完整备份与恢复 →「保存完整备份」；在系统保存对话框选位置 | 所有流水（含回收站）、微信/支付宝账户余额的计算基础、月预算、分类及图标和排序、快捷模板、周期规则及其生成月份 | 应用安装包及历史备份文件 | 换机、重装前留档、完整迁移 |
| CSV | 设置 →「导出 CSV」→ 分享到微信等应用，或「保存到本机」 | 流水字段：日期、金额、分类、备注、代付标记、支付账户、交易类型、转入账户、退款关联序号 | 回收站、账户余额的计算基础、预算、分类设置、模板、周期规则及其生成状态 | 与表格软件交换流水、只迁移流水 |
| 本机每日自动备份 | 每日首次启动应用时生成；恢复时点「选择本机备份恢复」 | 与完整 JSON 相同的账本数据 | 设备之外的副本 | 同一安装中的误删或误操作恢复 |

JSON 和 CSV 都是用户手动选择保存位置或分享目的地的文件。分享或保存到云盘、聊天、邮件等位置后，文件可能离开本机，访问权限由相应应用和保存位置决定。应用内检查更新也会连接 CDN 与 GitHub。

## 日常怎么备份

在「设置 → 完整备份与恢复 → 保存完整备份」导出 JSON，并另存电脑、另一台设备或网盘。记账较多时定期保存；准备大量修改、清空导入、卸载或换机前再保存一份。备份不需要 Root。

保存到手机的「下载」目录便于查找，但手机损坏、丢失或恢复出厂时仍可能一起丢失。至少保留一份设备之外的完整 JSON，并确认另一处能看到实际文件。保留不同日期的几份文件，便于选回正确状态。

## 保存完整备份并换机

1. 在旧设备打开「设置 → 完整备份与恢复 → 保存完整备份」。
2. 在系统文件保存对话框选择一个容易找到的位置。默认文件名为 `记账完整备份-yyyyMMdd-HHmmss.json`，其中日期时间取导出时刻。
3. 把该 JSON 文件放到新设备可访问的位置，例如电脑、U 盘、云盘或发送给自己。确认传输完成后再处理旧设备。
4. 在新设备安装 ExpenseTracker，打开「设置 → 完整备份与恢复 → 从完整备份文件恢复」，从系统文件选择器选 JSON。
5. 检查摘要中的备份时间、流水/回收站数量、账户数量、预算、分类、周期规则和模板。确认这是要恢复的账本后，点「覆盖并恢复」。

恢复后核对主要流水、账户余额、预算和周期规则。备份只包含导出时已有的数据，备份以后新记的流水不会自动回来；迁移期间继续在旧设备记账，需要重新导出最新文件。

完整恢复会替换当前设备内的全部流水（包括回收站）、账户余额的计算基础、月预算、分类、模板和周期规则。它不会把两台设备的数据合并。恢复前应用会在本机保存当前状态作为保护备份；如果恢复成功后才发现选错文件，可用「选择本机备份恢复」查看并恢复那份保护副本。保护文件名固定为最近一次 `before-restore.json`，下一次完整恢复或 CSV 清空导入会覆盖它，因此不要把它当作长期备份。

## 卸载、清数据或恢复出厂设置

本机自动备份和恢复前保护文件位于应用私有存储中。卸载应用或清除应用数据会移除这些本机文件；恢复出厂设置也不能依赖它们恢复。应用允许 Android 系统备份，但系统或厂商是否实际备份、迁移哪些内容，取决于设备和设置，不能用它代替可验证的外部副本。

要保留数据，先将完整 JSON 用「保存完整备份」写到设备之外，并确认文件可在另一处找到。重新安装后使用「从完整备份文件恢复」。若只在原设备上误删了记录，且应用数据还在，可先检查回收站或本机自动备份。

如果卸载、清数据或手机损坏后没有外部 JSON，也没有系统或厂商实际恢复的数据，应用无法凭空找回原账本。若只剩 CSV，可以恢复其中的流水，再手动设置实际账户余额、预算、模板和周期规则。

## 同机误删与恢复保护

- 左滑删除的流水会进入「设置 → 回收站」，最多保留 30 天。选中记录后点「恢复」可放回账本；恢复支出时其关联退款也会按记录关系一并恢复。
- 本机自动备份在每日首次启动成功生成完整 JSON，保留最近 7 份；失败会在下次启动重试。它不是每保存一笔就更新，也不会在应用关闭时后台定时生成。普通用户无需到文件管理器寻找私有目录，直接在设置的恢复列表中选择即可。
- 需要回到某个自动备份时，点「设置 → 完整备份与恢复 → 选择本机备份恢复」，选「自动备份 · 日期」，检查摘要，再确认「覆盖并恢复」。
- 完整 JSON 恢复会先建立 `恢复前的保护备份`。CSV 选择「清空后导入」前也会建立该保护文件。它只保留最近一次保护状态；后续任何一次上述操作都可能替换它。
- 永久删除回收站记录、等待 30 天自动清理后，优先使用尚保留且包含该记录的自动备份或外部 JSON。自动备份只保留 7 份。

## 在已有账本的设备导入

从「设置 → 完整备份与恢复 → 从完整备份文件恢复」选择 JSON，检查摘要后确认「覆盖并恢复」。恢复会完整替换当前账本，不支持合并两个账本。操作前先把目标设备的当前账本另存为外部完整 JSON，再进行覆盖；本机保护文件只有最近一次。若只是要加入另一份流水，可用 CSV「合并导入」，但应先核对与已有流水是否重叠。

如果系统文件选择器选错文件，可取消摘要，不会执行恢复。缺字段、格式损坏、校验失败或应用不支持的更新格式会拒绝恢复；确认前先查看错误信息，重新从原设备导出一份完整 JSON，或选择正确文件。不要把 APK、CSV 或本机旧 `.db` 快照当作完整 JSON 恢复文件。

## CSV 导出、分享与导入

### 导出

1. 打开「设置 → 导出 CSV」。
2. 选择「分享到微信等应用」并在系统分享面板选择微信、文件传输助手等目的地；或选择「保存到本机」，在系统保存对话框选下载、文档等位置。
3. 分享后请在目标应用中确认文件已发送。保存本机后记下保存位置。

CSV 导出全部月份中未删除的流水，不受当前月份或搜索筛选影响；不含已在回收站中的记录。九列文件可保存四类流水；退款用文件内序号关联原支出，因此完整导出时原支出和退款会保留关联。CSV 不能用来保存余额的计算基础、预算、规则或回收站。

### 导入

有两种入口：

- 本机文件：点「设置 → 导入 CSV → 从本机文件选择」，在系统文件选择器中选文件。
- 微信或其他应用收到文件：在微信中点开 CSV，右上角点「···」→「用其他应用打开」→ 选择「记账」。也可在其他支持分享文件的应用中用系统的打开方式。

如果打开方式中找不到「记账」，先把 CSV 下载到手机，再用「从本机文件选择」。完整 JSON 请走「从完整备份文件恢复」，不要从 CSV 入口导入。

随后会出现「导入数据」对话框：

- 「合并导入」：保留已有流水，并把 CSV 中每一条有效流水追加为新记录。程序不会检查或删除与已有记录重复的流水；重复导入同一个文件会再增加一份。分类名若设备上不存在会新增分类，现有账户余额的计算基础、预算、模板和周期规则保留。导入后，账户显示余额会按保留的余额计算基础和当前所有流水重新计算，因此数值可能变化。
- 「清空后导入」：先保存当前账本到本机恢复前保护文件，再清空流水表（包括回收站）并导入文件。它仍保留账户余额的计算基础、预算、已有分类、快捷模板和周期规则；缺少的流水分类会补建。周期规则的当月生成状态也会保留，避免清掉本月流水后再次生成。账户余额会根据保留的余额计算基础与导入后的流水重新计算。

两种导入方式都不把 CSV 当成完整备份。CSV 不含预算、账户余额的计算基础或规则；换机优先恢复 JSON。文件读取或校验失败时不会覆盖账本，数据库写入失败会回滚本次操作；旧格式允许跳过无效行，导入后应核对提示中的成功与跳过数量。

### CSV 格式兼容

当前导出为 UTF-8 编码，九列为：日期、金额、分类、备注、代付、支付方式、类型、转入账户、原记录序号。它支持支出、收入、转账、退款；退款需在同一 CSV 中带有对应原支出，并用序号关联。用表格软件编辑时，不要破坏退款关联序号或删除被退款引用的原支出。账户余额仍是应用按余额计算基础和流水计算出来的结果，不会写进 CSV。

旧版 3 至 6 列 CSV 仍可导入，旧记录会按支出处理，缺少的支付账户留空；旧文件中的无效行会跳过，并显示导入与跳过数量。当前九列格式若有缺列、无效交易类型、错误退款关联或不合法字段，文件会被拒绝，不会悄悄把错误数据当成有效流水导入。CSV 中有账户字段时也不会自动把未关联的旧流水分配到微信或支付宝。

这里兼容的是本应用导出的 CSV 格式，不保证支付宝或微信原生账单 CSV 可以直接导入。

旧设备如果只能导出 CSV，先保留原文件副本，再导入新设备。导入后手动校准实际账户余额、设置预算、重建模板和周期规则；核对完成后再保存一份完整 JSON，作为今后的迁移备份。

## 导错、重复导入或恢复失败

| 情况 | 处理方法 |
|---|---|
| 重复执行了 CSV「合并导入」 | 不要再次导入同一文件；少量重复可核对后删除，大量重复可恢复导入前另存的完整 JSON。合并导入本身不会生成恢复前保护文件 |
| 完整恢复选错文件，或 CSV「清空后导入」后想回退 | 打开「设置 → 完整备份与恢复 → 选择本机备份恢复 → 恢复前的保护备份」，先看摘要再恢复。完整恢复与 CSV 清空共用同一个 `before-restore.json`，只保留最近一次 |
| 备份太旧，恢复后少了最近记录 | 恢复不会找回备份以后的流水。先保留现状，找更新的完整 JSON；若从 CSV 补记，只追加缺失部分并核对重叠 |
| 恢复后找不到某一笔 | 先检查账本月份并清除搜索和筛选，再核对备份时间；备份之后才新增的记录不在这份文件中 |
| 提示备份来自新版应用或数据版本较新 | 升级到支持该备份的正式版再恢复；不要手改 JSON 的版本号绕过校验 |
| 文件无法读取、损坏或校验失败 | 确认文件已完整下载，重新选择，必要时从原设备重新导出。读取和校验失败不覆盖现有数据；写入失败会回滚 |

保护备份也通过完整恢复覆盖账本。回退前若已有需要保留的新流水，先另存外部完整 JSON；每次完整恢复都会替换保护文件。

| 文件 | 正确用途 |
|---|---|
| 本应用导出的 `.json` | 通过完整备份恢复入口还原账本 |
| 本应用导出的 `.csv` | 通过 CSV 导入入口追加或替换流水 |
| 旧版本机 `.db` 快照 | 当前 JSON 恢复入口不支持直接恢复；若旧设备仍能打开账本，先从当前应用导出完整 JSON |
| `.apk` | 应用安装包，不包含你的账本；不能当作备份恢复 |

改扩展名不会转换文件格式。

## 预算、余额与规则是不同数据

- **月预算**是消费计划，按当月净支出计算剩余额；收入和转账不占消费预算，退款按发生月份冲减净支出。CSV 不携带预算，完整 JSON 会保存。
- **账户余额**根据手动设置或校准的金额，结合流水变动计算。CSV 只带流水，导入后应核对并按实际余额校准；完整 JSON 同时保存余额的计算数据与流水。
- **周期规则**是未来生成流水的设置，完整 JSON 保存规则及已生成月份；CSV 不保存规则。CSV 清空流水时，为防止周期账单在本月重复生成，会保留规则的当月生成状态。
- **退款**需要关联原支出。CSV 九列通过文件内序号恢复关联；旧格式没有交易类型和关联字段，只能按普通支出导入。

当前没有照片附件备份、ZIP 迁移包或微信/支付宝自动付款识别与记账功能。

## 双设备迁移不是自动同步

应用没有云端账本同步。把 JSON 或 CSV 手动发送到另一台设备，只会复制当时导出的数据；两边之后新增或修改的记录不会自动互相更新。再次迁移需要重新导出并按本指南恢复或导入。若两台设备都已记账，完整 JSON 恢复会覆盖目标设备；CSV 合并则会追加所有行且不去重，应先核对并妥善备份目标账本。
