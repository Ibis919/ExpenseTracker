## Purpose

为记账和编辑表单提供便捷的四则金额计算，并让用户在确认结果后将其填入当前表单，同时保持账务保存由原有表单操作控制。

## ADDED Requirements

### Requirement: 用户可从金额输入框打开计算器

系统 MUST 在记账和编辑表单的金额输入框右侧提供计算器入口。打开计算器 MUST 隐藏系统键盘，并带入当前金额；当前金额为空时，计算器以0起始。关闭/返回 MUST 保留打开前的表单金额，且 MUST NOT 自动保存流水。用户直接输入普通金额时，系统 MUST 沿用既有金额解析行为。

#### Scenario: 打开和关闭计算器
- **WHEN** 用户打开计算器并在未填入的情况下关闭弹层
- **THEN** 表单金额与打开前相同，且没有新流水被保存

#### Scenario: 入口位于金额栏右侧
- **WHEN** 用户查看记账或编辑表单
- **THEN** 计算器入口显示在金额输入框右侧

#### Scenario: 普通金额直接录入
- **WHEN** 用户不打开计算器而在金额栏输入有效普通金额
- **THEN** 表单按现有金额校验规则处理该值

### Requirement: 计算器支持限定的四则表达式

计算器 MUST 支持连续加、减、乘、除运算，并兼容 `*` 与 `/` 运算符。乘除 MUST 优先于加减，同优先级运算 MUST 从左至右执行。表达式 MUST 使用十进制语义；按等号或填入计算完整表达式时，结果 MUST 在表达式计算完成后以 HALF_UP 规则舍入到分，中间步骤 MUST NOT 先舍入到分。等号显示两位小数。等号后按运算符继续 MUST 使用屏幕显示的两位结果作为左值；按数字或小数点 MUST 开始新表达式。计算器 MUST NOT 支持括号、百分号、科学功能或记忆功能。

#### Scenario: 乘除优先且同级左结合
- **WHEN** 用户计算 `2+3×4` 和 `8÷4×2`
- **THEN** 结果分别为¥14.00和¥4.00

#### Scenario: 最终结果舍入到分
- **WHEN** 用户计算 `0.1+0.2`、`1÷3×3` 和 `1÷8`
- **THEN** 结果分别为¥0.30、¥1.00和¥0.13

#### Scenario: ASCII运算符兼容
- **WHEN** 用户使用 `*` 和 `/` 输入表达式
- **THEN** 系统分别将其按乘法和除法计算

#### Scenario: 等号后从显示值续算
- **WHEN** 用户先计算 `1÷3` 得到显示结果¥0.33，再按乘号并输入3
- **THEN** 后续算式以¥0.33作为左值；而在首次按等号前输入 `1÷3×3` 时不逐步舍入，结果为¥1.00

### Requirement: 等号只计算，填入才更新表单

按下等号 MUST 显示当前表达式及两位小数结果，且 MUST NOT 更新表单金额。用户按下填入时，系统 MUST 将有效结果写入当前表单金额，但 MUST NOT 自动保存流水。填入的金额 MUST 大于零且不超过¥9,999,999.99。无效表达式或无效结果 MUST 保留算式、显示文字提示并禁止填入。

#### Scenario: 等号预览不改变金额
- **WHEN** 用户输入 `19.3+2.36` 并按等号
- **THEN** 计算器显示¥21.66，原表单金额未改变

#### Scenario: 填入更新表单但不保存
- **WHEN** 用户对有效表达式按填入
- **THEN** 计算器关闭且表单金额更新为计算结果，流水仍需用户执行原有保存操作

#### Scenario: 无效金额不能填入
- **WHEN** 表达式结果为零、负值或超过¥9,999,999.99
- **THEN** 计算器保留表达式、显示文字错误并禁用填入，原表单金额不变

### Requirement: 计算器按键可编辑表达式并清楚呈现状态

计算器 MUST 提供数字、运算符、小数点、清空、退格、等号、填入和关闭操作。填入按钮 MUST 位于弹层右下角，等号 MUST 位于填入按钮正上方。配置变化（包括屏幕旋转）后 MUST 保留当前表达式与结果。计算器 MUST NOT 重复执行上次隐式运算。按键可操作区域 MUST 至少为48dp；交互状态 MUST 通过文字、图标语义或高对比边框表达，不能仅依赖颜色。

#### Scenario: 清空与退格
- **WHEN** 用户分别操作清空和退格
- **THEN** 清空删除整个表达式，退格只删除最后一个输入字符

#### Scenario: 从已显示结果继续
- **WHEN** 用户计算得到¥5.00后按加号并输入3
- **THEN** 新表达式按5+3计算；若用户改按数字键则开始新表达式

#### Scenario: 错误状态可辨认
- **WHEN** 计算器出现未完成表达式、除零或越界错误
- **THEN** 屏幕显示相应文字提示和明确的控件状态，在深浅色主题下均不只依靠颜色传达错误

#### Scenario: 除零和未完成表达式保留输入
- **WHEN** 用户分别输入 `10÷0` 或 `12+` 并尝试计算
- **THEN** 系统显示错误文字，保留原算式，且原表单金额不变、填入不可用

#### Scenario: 旋转后恢复计算状态
- **WHEN** 用户输入表达式或显示计算结果后旋转设备
- **THEN** 计算器保留原表达式与结果，用户仍可退格修正或继续输入

### Requirement: 计算器适配主题和大字号

计算器 MUST 沿用系统字体与应用深浅色主题，并在200%系统字号下保持表达式、结果、提示和操作按键可读且可操作。最终发布APK MUST 不超过50MB。

#### Scenario: 深浅色和大字号下操作
- **WHEN** 用户在深色或浅色主题、200%系统字号下打开计算器
- **THEN** 文字可读，至少48dp的按键可操作，填入与等号位置清楚且无关键内容被裁切

#### Scenario: 发布包大小
- **WHEN** 实现后的目标发布APK完成构建
- **THEN** 验收记录确认其文件大小不超过50MB
